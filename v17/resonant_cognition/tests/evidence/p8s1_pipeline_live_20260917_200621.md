## Bugs found & fixed during this segment (root causes, not patches)

1. **Pipeline Step 5 called `compute_resonance()` with a wrong signature** — it passed
   `(input_vec, base_dir=…)` but the real function takes `(axes: tuple3, anchors: dict, masses: dict)`.
   Fixed by using the canonical helper `resonance.resonance_for_input(text)` (embed → project_to_axes →
   compute with `SEMANTIC_ANCHORS` + `PLANET_MASSES`). The result is informational only and never gates.

2. **`resonance_for_input()` had a latent `NameError: name '_' is not defined`.** It ended with
   `return compute_resonance(…), _` — the trailing `_` was undefined (author meant to return just the
   tuple). This function was dead code until this segment wired it in, so it never surfaced. Now returns
   the `(results, state)` tuple directly.

3. **Gate 1 missed spaced-out keyboard smash** → caused the smoke test to HANG. `"aaaa aaaa …"` broke the
   char-run detector (spaces reset each run below threshold) and its letters were miscounted as "content
   words", so it was not blocked — and the smoke test then ran a full live LLM chamber instead of short-
   circuiting. Added a conservative low-diversity spam signal in `gate1.py`: if the whole string uses ≤2
   distinct letters and one letter recurs ≥6 times, reject as character spam. Verified it does NOT false-
   positive on legit repeated words (banana, hello) or normal prose. This is an intake-layer fix (where it
   belongs), not a paper-over in the pipeline or test.
